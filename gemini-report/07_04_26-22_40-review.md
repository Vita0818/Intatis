FINDINGS:
经过对 Intatis 项目架构和代码状态的只读审查，Intatis 作为一款原生的、Clean-room 本地 AI 工作区，与目前顶级的 Agent 工具（如 OpenCode, Cline, Cursor, Aider 等）在设计理念上存在显著差异。主要体现在以下几个核心架构抽象与安全策略上：

1. **去中心化、基于契约的多智能体协同 (Cowork)**
   - **顶级 Agent 工具现状**：大多数采用单智能体（Single Agent）架构（如 Cursor, Aider），或者采用硬编码的父子树状调用模型（Coordinator-Worker 递归模式）。
   - **Intatis 的差别**：坚持 `AgentLoop` 不得直接嵌套调用。引入了 **Agent Identity**（持久化身份）、**Task Contract**（任务契约）、**Capability Lease**（能力租约）和 **Scoped Context**（作用域投影上下文）。Agent 没有永久的上下级，而是通过 `MessageBus` 消息总线和 `Mediator` 进行通信与任务分派。

2. **极度严格的三层权限与安全拦截机制 (Security & Permissions)**
   - **顶级 Agent 工具现状**：主要依靠终端的用户确认（Y/N），或通过 Docker/Sandbox 进行简单的环境隔离。
   - **Intatis 的差别**：实现了一套复杂的进程内 3 层权限门：
     1. `DeterministicPolicyGate`：模型无关的硬性策略拒绝（如敏感路径、越界访问）。
     2. `ModelPermissionReviewer`：大模型参与的权限审查（只能收窄，不能放行）。
     3. `PermissionEngine`：基于上述两者的结合，最后才 fallback 到 `askUser`。
   - 更进一步，在 CLI 的 Cowork 模式下引入了自动权限审查专属保留子智能体 `@permission-reviewer`。而且框架拥有 `SecretScanner` 和 `Mediator`，能拦截智能体间通信里的 Secret 并限制长文本以防刷屏。

3. **事件溯源 (Event Sourcing) 与投影驱动的 GUI**
   - **顶级 Agent 工具现状**：往往将对话存储在 SQLite 或 JSON 中，直接把模型输出映射到 UI 侧，状态结构较扁平。
   - **Intatis 的差别**：所有的模型交互、工具调用、Token/耗时统计（`turn_stats`）都是写入 Append-only 的 `EventLog` (JSONL)。GUI 层并不直接解析模型回复文本，而是通过 `ConversationProjection`, `CodeProjection`, `TurnStatsProjection` 折叠事件状态来渲染。这种架构为之后的时间漫游（Time-travel）、故障恢复和重放（Replay）提供了坚实基础。

4. **真正的原生跨平台且边界清晰 (Native & Strict Platform Boundaries)**
   - **顶级 Agent 工具现状**：主要依赖 Electron/Web 技术栈（如 VSCode 插件）或 Python/Node.js CLI。
   - **Intatis 的差别**：采用全 Swift 编写。而且严格控制平台能力边界，macOS 提供全量 Chat/Code/Cowork，而 iOS 仅作为 Chat 子集暴露（不链接任何 AgentKernel / Tools 执行器），从二进制层面消除了移动端误执行本地破坏性代码的可能。

5. **配置生态的兼容性设计**
   - **顶级 Agent 工具现状**：各自维护独立的配置格式。
   - **Intatis 的差别**：采用 Clean-room 方式重构的同时，在配置层（Provider Catalog）推荐并直接兼容 `OpenCode-compatible` 配置 (`opencode.json`)。这意味着它可以零成本复用顶级开源产品构建好的配置与密钥管理习惯。

总体来说，Intatis 不追求简单的“大模型套壳+工具”，而是构建了一套工业级、高度解耦、强调安全边界和领域驱动设计（DDD）的本地多智能体操作系统（AgentKernel）。
