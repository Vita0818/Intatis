`MessageRenderingTests` 当前共 29 项。覆盖范围除既有 Markdown/inline-display math/standalone display/sole-inline provider route/货币/escaped-invalid-unclosed delimiter/公式数量与 bitmap/cache/stream identity/highlight.js/C/C++ fail-closed 外，还必须包括：单行 `CMARK_NODE_CODE` 直接 SOURCEPOS 映射；Unicode/multiline inline code；blockquote + list continuation prefix 下，多行 node 的末行在 closer 前仍含公式-like 文本；该嵌套用例对 LF、CR、CRLF 全覆盖；fenced/indented/nested `CMARK_NODE_CODE_BLOCK`；unmatched backtick 不跨 paragraph/fence 配对及递增长 backtick input 有界处理；paragraph 第 128/129 个 break；list 第 8/9 层；大 GFM table AST；wide inline tree；普通 GFM allow path；结构化 key 碰撞与 Unicode byte identity。生产 builder 只能在同一个 pinned cmark AST pass 中取 code ranges 与 complexity。多行 container case 仅允许用 cmark node `endLine` + `backtick_count` 在对应 raw 末行定位已知长度 closing run；不得把测试描述成“所有多行 SOURCEPOS 都可直接精确映射”，也不得恢复手写 opener pairing/code-span parser。测试总数仍为 29，本宿主 runnable 仍为 28/28。

当前 complexity 断言值为：paragraph soft+line breaks ≤128；每个 paragraph/heading/table-cell 的 non-break inline nodes ≤256；list nesting ≤8；总 AST nodes ≤4,096；tree depth ≤32。raw source 含任一 `\(` / `\[` / `$$` opener 时，为最多 64 个 math placeholders 预留 node 256、depth 1、inline-per-container 192，所以 raw gate 分别使用 3,840 nodes、31 depth、64 inline nodes。超限、cmark parser/extension attach 失败、未知 node、单行 SOURCEPOS→Swift range 失败，或多行 `endLine`/known backtick-count repair 无法证明 closing run，都必须整条 `.plain(rawText)`，不得构造部分 `MarkdownContent`。

上游回归依据必须持续跟踪 MarkdownUI 官方 [#312](https://github.com/gonzalezreal/swift-markdown-ui/issues/312)、[#426](https://github.com/gonzalezreal/swift-markdown-ui/issues/426)、[#445](https://github.com/gonzalezreal/swift-markdown-ui/issues/445) 和未合并 [PR #438](https://github.com/gonzalezreal/swift-markdown-ui/pull/438)。issue/PR 的复现数字不是稳定平台上限；PR #438 未合并前不得复制其 renderer 核心修复，只验证 Intatis 的 pre-render fail-closed gate。

## 开源复用验证

引入、翻译、vendor、链接或升级上游源码/公开 prompt/runtime 时，除功能测试外必须完成：

- 记录上游 URL、固定 tag/commit、具体文件、原许可证和本地修改摘要。
- 核对目标文件头、根 LICENSE、NOTICE、传递依赖和资产许可证；结果写入 `NOTICE.md`，需要完整分发文本时写入 `ThirdPartyNotices/<project>.md`。
- 说明复用形式是 `derived`、`vendored`、`dependency` 还是 `external-runtime`；逐行翻译不能记成独立实现。
- 对 Apple 平台运行 `swift build` 及受影响 target 的测试；涉及 macOS helper/runtime 时还要验证 code signing、bounded timeout/cancel/process cleanup 和缺失 runtime 的失败降级。
- 验证外部实现仍经过 PermissionEngine、CapabilityLease、WorkspaceLease、PathConfinement、durable tool execution 与 EventLog；上游默认 allow/网络/文件能力不得直接继承。
- 确认 iOS target 没有因复用新增 shell/git/local-agent/Cowork 或非允许 runtime 链接。
- 升级 pinned upstream commit 时重新检查许可证/NOTICE/依赖变化和本地 patch，不得只验证编译通过。
